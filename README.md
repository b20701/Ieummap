# 이음맵 v7.3 — 서버 프록시 공개 배포판

휠체어 이용자가 서울 지하철역의 접근성 시설 정보를 확인하는 웹사이트입니다.
방문자는 인증키나 API 주소를 입력하지 않고 공개 URL에 접속만 하면 됩니다.

- 엘리베이터 (`getWksnElvtr`, 열린데이터광장 OA-22740)
- 휠체어 급속충전기 (`getWksnWhclCharge`, OA-22745)
- 휠체어 리프트 (`getWksnWhcllift`, OA-22743)
- 교통약자 도우미 (`getWksnHelper`, OA-22748)
- 장애인 화장실 (`getWksnRstrm`, OA-22741)

## 동작 방식

```
브라우저(app.js) ──HTTPS──▶ /api/facilities?type=elevator (Vercel 함수)
                                   │  SEOUL_API_KEY 환경변수 사용
                                   ▼
                  http://openapi.seoul.go.kr:8088/{키}/xml/getWksnElvtr/1/1000/
```

- 서울시 Open API는 HTTP(8088)만 제공합니다. HTTPS 페이지에서 브라우저가 직접 부르면 차단되므로 서버가 대신 호출합니다.
- **실제 응답 형식 (2026-10 확인):** 공공데이터포털 형식입니다.
  - `resultCode` `00`, `resultMsg` `NORMAL_CODE`
  - `items`/`item`, 끝에 `pageNo`·`numOfRows`·`totalCount`
  - 서울 열린데이터광장 표준 형식(`<row>`, `<RESULT><CODE>`)도 함께 해석합니다.
- **1,000건 초과:** `totalCount`를 보고 나머지 페이지를 자동으로 받습니다.
  - 서울시 게이트웨이가 2페이지 주소를 어떻게 바꾸는지 확인되지 않았습니다.
  - 그래서 먼저 표준 방식(`/1001/2000/`)으로 요청하고, 새 데이터가 없으면 페이지 번호 방식(`/2/1000/`)으로 다시 시도합니다.
  - 실제로 쓰인 방식은 응답의 `pagingMode`(`range` 또는 `page`)에 표시됩니다.
- 성공한 응답은 5분 동안 캐시됩니다(서버 메모리와 Vercel CDN). 오류는 캐시하지 않습니다.
- 다섯 서비스를 각각 따로 불러옵니다. 하나가 실패해도 나머지는 표시됩니다.
- 인증키는 응답과 로그에 절대 넣지 않습니다(자동 테스트로 확인).

## 환경변수

| 이름 | 설명 |
| --- | --- |
| `SEOUL_API_KEY` | 공통 인증키. 하나의 키로 다섯 서비스를 모두 쓸 때 |
| `SEOUL_API_KEY_ELEVATOR` | (선택) 엘리베이터 전용 키 |
| `SEOUL_API_KEY_CHARGER` | (선택) 휠체어 급속충전기 전용 키 |
| `SEOUL_API_KEY_LIFT` | (선택) 휠체어 리프트 전용 키 |
| `SEOUL_API_KEY_HELPER` | (선택) 교통약자 도우미 전용 키 |
| `SEOUL_API_KEY_TOILET` | (선택) 장애인 화장실 전용 키 |

- 서비스 전용 키가 있으면 공통 키보다 먼저 씁니다.
- 서비스마다 다른 키를 발급받았다면 다섯 개의 전용 키를 모두 넣으세요.
- 값은 요청 주소 `http://openapi.seoul.go.kr:8088/{인증키}/xml/...`의 `{인증키}` 부분입니다. `8088/` 뒤부터 `/xml` 앞까지만 넣으세요.
- URL 전체나 따옴표를 넣으면 화면에 설정 오류로 안내됩니다.

## 로컬 테스트

Node.js 18 이상이 필요합니다(`node -v`로 확인).

```bash
# 1) 자동 테스트: 서버 프록시 23개 항목 (인터넷·인증키 불필요)
npm test

# 2) 모의 데이터로 화면 확인 (인증키 불필요)
npm run mock                 # → http://localhost:3000
node scripts/dev-server.js --mock-fail=lift,toilet --mock-timeout=helper   # 오류 화면 확인

# 3) 실제 서울시 API로 확인
cp .env.example .env.local   # Windows: copy .env.example .env.local
#    .env.local에 인증키 입력 후
npm start                    # → http://localhost:3000
```

실제 API 모드에서 확인할 주소:

- `http://localhost:3000/api/facilities`
  - 다섯 서비스 모두 `"configured": true`여야 합니다. 키 값은 표시되지 않습니다.
- `http://localhost:3000/api/facilities?type=elevator`
  - `"ok": true`와 `"count"`가 0보다 커야 합니다.
  - 오류이면 `error.cause`(원인)와 `error.operatorAction`(해결 방법)을 확인하세요.

`index.html`을 더블클릭해서 열면(file://) 서버 기능이 없어 데이터를 불러올 수 없습니다. 화면에도 그렇게 안내됩니다.

## 공개 URL 체크리스트

1. `https://<도메인>/api/facilities`
   - JSON이 보여야 합니다.
   - 다섯 서비스 모두 `"configured": true`여야 합니다.
   - `"region": "icn1"`이어야 합니다(서울 리전 적용 확인).
2. `https://<도메인>/api/facilities?type=elevator`부터 `charger`, `lift`, `helper`, `toilet`까지 차례로 엽니다.
   - 각각 `"ok": true`이고 `count`가 0보다 커야 합니다.
   - `"partial": false`이고 `count`가 `totalCount`와 같아야 합니다.
   - 2026-10 기준 참고값: 충전기 119, 리프트 43, 도우미 21, 화장실 303.
   - **엘리베이터**는 1,000건을 넘을 수 있습니다. `"partial": true`이고 `warning.code`가 `PAGINATION_UNSUPPORTED`이면 2페이지 수집이 실패한 것입니다. `warning.operatorAction`의 안내대로 두 주소를 비교해 주세요.
   - 각 응답의 `records[0]`에서 **실제 필드 이름**을 확인할 수 있습니다. 모르는 필드에 한글 라벨을 붙일 때 사용하세요(`app.js`의 `FIELD_LABELS`).
3. 첫 화면 오른쪽 위 표시가 **"공공데이터 연결됨"**이어야 합니다. "일부 연결됨"이면 ⚙에서 원인을 확인하세요.
4. ⚙ 데이터 연결 상태
   - 다섯 줄 모두 "연결됨"이어야 합니다.
   - URL이나 인증키 입력칸은 없어야 합니다.
5. 빠른 검색(시청역·서울역·강남역)과 직접 검색으로 시설 카드를 확인합니다.
   - 운영 상태(사용 가능·점검 중 등)와 상세 위치가 보여야 합니다.
6. 검색창에 두 글자를 입력하면 역 이름 자동완성이 떠야 합니다.
7. '시설' 필터를 바꾸면 해당 종류만 보여야 합니다.
8. 휴대폰에서 접속해 가로 스크롤이 없는지, 검색 버튼이 잘리지 않는지 확인합니다.
9. 제보 등록 후 새로고침해도 제보가 남아 있어야 합니다. 다른 기기에서는 보이지 않는 것이 정상입니다.
10. 브라우저 개발자도구 → Network에서 `/api/facilities` 응답을 엽니다. 인증키가 어디에도 없어야 합니다.
11. 페이지 소스(`app.js`)에 `openapi.seoul.go.kr`이나 인증키가 없어야 합니다.
12. Vercel → 배포 → **Logs**에 반복되는 오류가 없는지 확인합니다.

## 오류 안내

화면과 API 응답은 오류를 **원인 / 해결 방법(이용자) / 운영자 확인**으로 나눠 보여줍니다.

| 코드 | 의미 | 운영자 조치 |
| --- | --- | --- |
| `CONFIG_MISSING_KEY` | 환경변수에 키가 없음 | Vercel 환경변수 추가 후 Redeploy |
| `CONFIG_KEY_LOOKS_LIKE_URL` | 키 자리에 URL 전체가 들어감 | 키 부분만 입력 |
| `CONFIG_INVALID_KEY` | 공백·따옴표 등 잘못된 문자가 섞임 | 값 다시 입력 |
| `SEOUL_INFO-100` | 서울시가 인증키 거부 | 키 확인. 서비스별 키라면 해당 `SEOUL_API_KEY_*` 사용 |
| `SEOUL_INFO-300` / `INFO-400` | 키 사용 제한 / 서비스 권한 없음 | 열린데이터광장 마이페이지 확인 |
| `SEOUL_ERROR-310` | 서비스명을 찾을 수 없음 | 서비스명 변경 여부 확인 (`api/facilities.js`의 `SERVICES`) |
| `SEOUL_ERROR-337` | 일일 호출 한도 초과 | 다음 날 초기화 |
| `SEOUL_ERROR-500/600/601` | 서울시 서버 오류 | 잠시 후 재시도, 점검 공지 확인 |
| `UPSTREAM_TIMEOUT` | 8초 안에 응답 없음 (1회 재시도) | `icn1` 리전 적용 여부, 서울시 상태 확인 |
| `UPSTREAM_UNREACHABLE` | 서버가 서울시 API에 연결 실패 | Functions 로그 확인 |
| `UPSTREAM_NOT_XML` | 점검 페이지 등 XML이 아닌 응답 | 샘플 URL 직접 확인 |
| `API_NOT_FOUND` (화면) | `/api/facilities` 없음(404) | Vercel에 api 폴더 포함 배포. GitHub Pages는 불가 |
| `FILE_PROTOCOL` (화면) | index.html을 파일로 직접 열었음 | `npm start` 사용 |

## 데이터 필드와 표시 규칙

- **확인된 필드 (엘리베이터):**
  - `stnNm`(역명), `lineNm`(호선), `dtlPstn`(상세 위치), `oprtngSitu`(운영 상태), `fcltNm`(시설명)
  - `bgngFlr`/`endFlr`와 `…GrndUdgdSe`(층·지상/지하), `pscpNope`(정원), `pscpWht`(적재 하중), `vcntEntrcNo`(인근 출입구), `crtrYmd`(기준일) 등
- **운영 상태 코드 (서울교통공사):**
  - `M` 사용 가능 / `S` 보수 중 / `T` 운행 중지 / `I` 점검 중 / `B` 공사 중
  - `D` 삭제는 목록에서 제외합니다.
- **실제 응답에서 확인한 값 (2026-10, 이용자가 휴대폰 Safari로 저장한 PDF):**
  - Safari는 XML 태그를 숨기고 값만 저장하므로 **필드 이름은 PDF에 없습니다.** 값의 순서와 내용만 확인했습니다.
  - 엘리베이터: 시설번호 → 시설명(`승강기)엘리베이터-동묘앞 …#1`) → 호선 → 역코드 → 역명 → 역번호 → 기준일 → 내부/외부 → 호기 → 인근 출입구(`1,10` 또는 `내부`) → 상세 위치 → 층(`지하`+`B1`, `지상`+`4`) → 정원 → 하중 → 관리번호 → 상태(`M`/`S`)
  - 휠체어 리프트: 엘리베이터와 비슷하며 상태 `M`/`S`가 있습니다.
  - 휠체어 급속충전기: 시설명(`전동휠체어 충전설비-`), 호선, 역, `기타`, 층, 대수, 상세 위치, 기준일, 지상/지하가 있고 **상태 값은 없습니다.**
  - 교통약자 도우미: 역명·역코드·역번호·호선·전화번호·기준일만 있고 **위치 값이 없습니다.** 화면은 전화번호를 찾아 "도움 요청 전화"와 전화 걸기 링크로 보여줍니다.
  - 장애인 화장실: 시설명(`건축)대합실화장실-…`), 개찰구 내부/외부, 지상/지하, 인근 출입구, 상세 위치, 구성(`일반(남,여) / 교통약자(남,여)`), 층, Y/N 값이 있습니다.
- **화면 표시 규칙:**
  - 시설명 앞 분류어(`승강기)`, `건축)`)와 끝의 `-`는 빼고 보여줍니다.
  - `B1`은 "지하 1층"으로 바꿔 보여줍니다.
  - 인근 출입구 `1,10`은 "1, 10번 출입구"로 바꿔 보여줍니다.
  - 필드 이름을 모르는 항목은 한글 라벨을 추정하고, 추정이 안 되면 원래 이름 그대로 보여줍니다.
- **필드명 형식:** `stnNm` 같은 낙타 표기와 `STN_NM` 같은 대문자·밑줄 표기를 같은 필드로 봅니다. 실제 응답이 어느 형식이어도 역 매칭, 운영 상태, 위치, 층 구간이 똑같이 표시됩니다.
- **역명 매칭:**
  - 공백, 끝의 '역', 괄호 부역명 차이를 무시합니다. 예: 충정로 = 충정로(경기대입구), 서울역 = 서울
  - 역명 필드가 없는 데이터셋만 전체 텍스트로 검색합니다.
- **데이터 범위:**
  - 서울교통공사 운영 구간만 포함됩니다.
  - 코레일, 9호선, 신분당선 등 다른 운영기관 구간의 시설은 없을 수 있습니다.
  - '정보 없음'이 시설이 없다는 뜻은 아닙니다.

## 실제 필드 이름 확인 방법

휴대폰 Safari로 서울시 API 주소를 열면 XML 태그가 숨겨지고 값만 보입니다. 그래서 필드 이름을 알 수 없습니다. 아래 방법 중 하나를 쓰세요.

1. **(가장 쉬움) 배포된 사이트의 ⚙ 데이터 연결 상태**
   - 서비스마다 **"필드 이름 N개 보기"**를 누릅니다.
   - 실제 응답의 필드 이름, 화면에서 쓰이는 방식, 예시 값이 표로 나옵니다.
   - "미확인"으로 표시된 줄(노란 배경)이 아직 한글 라벨이 없는 필드입니다.
   - **"필드 이름 복사"**를 누르면 메시지에 붙여 넣을 수 있는 목록이 복사됩니다.
2. **배포 주소의 JSON:** `https://<도메인>/api/facilities?type=toilet`을 엽니다. JSON은 휴대폰에서도 필드 이름이 그대로 보입니다(`records` 안의 `"이름": 값`).
3. **PC 브라우저:** Chrome·Edge·Firefox로 서울시 API 주소를 열면 XML 태그가 트리 형태로 보입니다.

확인된 필드 이름은 `app.js`의 `FIELD_LABELS`에 `필드이름:"한글 라벨"` 형태로 추가하면 화면에 반영됩니다.

## 이용자 제보의 저장 방식과 한계

- 브라우저 `localStorage`(`ieummap-reports-v2`)에만 저장됩니다.
- 그래서 다음과 같은 한계가 있습니다.
  - **공유되지 않음:** 등록한 기기·브라우저에서만 보입니다.
  - **유실 가능:** 브라우저 데이터 삭제, 사생활 보호 모드, 다른 기기에서는 사라지거나 보이지 않습니다.
  - **검토 없음:** 모든 제보가 '미확인'으로 표시됩니다. '확인 기록 있음' 필터는 현재 비어 있습니다.
- 여러 이용자가 제보를 공유하려면 다음이 필요합니다.
  - 서버 저장소(예: Vercel Marketplace의 DB)
  - 검토·삭제 절차
  - 스팸 방지
  - 개인정보 처리 방침
